`eval_program_raw` evaluates deeply nested `Data` arguments without exhausting the stack. Arguments are decoded straight into the evaluator's own `Data`, whose decoding, comparison, serialisation and release never recurse, instead of through pallas' recursive `PlutusData`, so an argument nested 100,000 levels deep evaluates like any other, in both the speed and size builds. Arguments are now decoded exactly as Plutus' `decodeData` decodes them. A byte string or big integer with a chunk of more than 64 bytes, a big integer tag outside the head of its own byte, or a tag 102 constructor that is not a pair of an index and fields is refused as an invalid argument, as it can never be Data on chain. A big integer in indefinite-length chunks and a tag 102 in a longer head, which pallas refused, are accepted. A tag 102 constructor in an indefinite-length array inside a list or map, which pallas closed one break too early and so decoded to different Data, now decodes to the Data Plutus decodes. Every other argument decodes to the same Data as before, with the same results and ex-units.
